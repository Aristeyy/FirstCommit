# Первый коммит

**Чат-бот и мини-приложение в MAX, которые помогают студентам IT-направлений найти первую стажировку под свой профиль и не пропустить дедлайн набора.**

Трек «Образовательные решения» → направление «Карьера и стажировки».

## 1. Назначение

Студент 2–4 курса IT-специальности, который ищет первую стажировку, вынужден вручную мониторить десятки карьерных сайтов с разными сроками набора, требованиями к курсу и форматами работы. Из-за этого он пропускает дедлайны и тратит часы на поиск.

«Первый коммит» собирает стажировки из нескольких источников, ранжирует их под профиль студента с объяснением («почему подходит») и напоминает в чате о дедлайнах отслеживаемых программ.

## 2. Основной пользовательский сценарий

1. Пользователь открывает бота в MAX → «Начать».
2. Бот задаёт 3 вопроса кнопками: направление, курс, город/удалёнка.
3. Бот показывает итог («нашёл N стажировок, у K дедлайн в ближайшую неделю») и кнопку **«Открыть подборку»**.
4. В мини-приложении — подборка, отсортированная по соответствию профилю. Фильтры: направление, стек, формат, город, статус набора, оплата, курс. Поиск по тексту.
5. Карточка стажировки: процент соответствия и причины, сроки (старт набора → дедлайн → начало), требования, этапы отбора, источник и дата обновления, кнопки «Подать заявку на сайте», «Напомнить о дедлайне», «Поделиться».
6. Бот присылает напоминания за 7, 3 и 1 день до дедлайна отслеживаемой программы. Кнопка в уведомлении открывает мини-приложение **сразу на этой карточке** (диплинк через `start_param`).

**Результат для пользователя:** заявка подана вовремя, без ручного мониторинга сайтов.

## 3. Состав и архитектура

```
Пользователь MAX ──чат──► Bot API MAX ◄──long polling── bot ─┐
        │                       ▲                            │
        │                       └──── уведомления ── worker ─┤── PostgreSQL
        └──мини-приложение (HTTPS)──► web (Caddy) ──/api──► api ─┘
                                        │ статика React     ▲
                                  tunnel (Cloudflare)   worker: сбор данных
                                                        (Работа России, Хабр Карьера, справочник)
```

| Сервис | Назначение | Технологии |
|---|---|---|
| `db` | Хранилище: стажировки, источники, пользователи, отслеживание, журнал уведомлений | PostgreSQL 16 |
| `api` | REST API мини-приложения, проверка подписи `initData`, поиск и скоринг | Node.js 22, TypeScript, Fastify, zod |
| `bot` | Сценарии чат-бота: онбординг, меню, топ-3, отслеживание | официальный SDK `@maxhub/max-bot-api` |
| `worker` | Периодический сбор данных и отправка уведомлений | тот же образ, что api/bot |
| `web` | Раздача мини-приложения, прокси `/api` | React 19, Vite, MAX UI, MAX Bridge, Caddy |
| `tunnel` *(профиль)* | Публичный HTTPS-адрес без VPS и домена | cloudflared (Quick Tunnel) |

Структура репозитория:

```
backend/
  src/api/        REST API и проверка initData
  src/bot/        сценарии бота и форматирование сообщений
  src/domain/     ядро: справочники, классификация, скоринг, поиск
  src/parsers/    адаптеры источников + общий раннер
  src/notify/     напоминания и дайджесты
  src/db/         пул, миграции, запросы
  seed/           справочник программ и снимки источников
  scripts/        обновление снимков источников
miniapp/src/      мини-приложение (экраны, компоненты, обёртка MAX Bridge)
infra/            Caddyfile, корневые сертификаты Минцифры
compose.yaml      все компоненты одной командой
```

Api, bot и worker — **один образ** с разными командами: общая доменная логика, одна сборка.

## 4. Запуск одной командой

Требуется Docker (Docker Desktop или Docker Engine + Compose v2).

```bash
cp .env.example .env        # вписать MAX_BOT_TOKEN
docker compose up -d --build
```

Мини-приложение будет доступно на http://localhost:8080. Для открытия внутри MAX нужен публичный HTTPS-адрес:

```bash
docker compose --profile tunnel up -d
docker compose logs tunnel | grep trycloudflare.com   # Windows: findstr trycloudflare
```

Полученный адрес `https://….trycloudflare.com` указывается как URL мини-приложения в настройках бота на платформе MAX для партнёров. При наличии своего домена туннель не нужен: достаточно направить HTTPS-прокси на порт `WEB_PORT`.

### Подключение мини-приложения к боту

Мини-приложение в MAX открывается только из бота, к которому привязан его URL: платформа MAX для партнёров → «Чат-боты» → ⋮ → «Настройки» → поле URL мини-приложения. Требования: HTTPS, до 1024 символов. После сохранения в чате с ботом появляется кнопка запуска, и начинают работать кнопки «Открыть подборку» из сообщений бота.

### Постоянный HTTPS-адрес на VPS (рекомендуется для проверки)

Адрес туннеля меняется при перезапуске, туннель работает, только пока включён компьютер, и **из России открывается только через VPN**. Поэтому для проверки нужен постоянный адрес на VPS. Для проверки жюри нужен постоянный адрес. Покупать домен не нужно: Caddy сам выпускает сертификат Let's Encrypt, а имя даёт sslip.io.

```bash
# на VPS с Docker, порты 80 и 443 открыты; IP сервера 1.2.3.4
git clone <repo> && cd <repo> && cp .env.example .env   # вписать MAX_BOT_TOKEN
SITE_ADDRESS=1-2-3-4.sslip.io docker compose -f compose.yaml -f compose.vps.yaml up -d --build
# URL мини-приложения: https://1-2-3-4.sslip.io
```
Время сборки: **около 40 секунд** на чистой машине (без учёта загрузки базовых образов — меньше), лимит кейса — 5 минут.

## 5. Параметры и переменные окружения

Все переменные описаны в `.env.example`. Рабочих значений в репозитории нет.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `MAX_BOT_TOKEN` | да | Токен бота MAX. Используется ботом, воркером и для проверки подписи `initData` |
| `MAX_API_BASE` | нет | Адрес Bot API, по умолчанию `https://platform-api2.max.ru` |
| `MAX_BOT_USERNAME` | нет | Ник бота для кнопок мини-приложения; если пуст — берётся из `GET /me` |
| `WEB_PORT` | нет | Порт мини-приложения на хосте (8080) |
| `API_PORT` | нет | Порт API внутри сети Docker (3000) |
| `SESSION_SECRET` | нет | Секрет подписи сессий; если пуст — выводится из токена |
| `SESSION_TTL_HOURS` | нет | Время жизни сессии мини-приложения (24) |
| `INIT_DATA_MAX_AGE_SEC` | нет | Допустимый возраст `initData` (86400) |
| `ALLOW_DEV_AUTH` | нет | `true` — вход демо-пользователем в обычном браузере. **Только для отладки** |
| `POSTGRES_USER/PASSWORD/DB` | нет | Учётные данные БД (по умолчанию `firstcommit`) |
| `DATABASE_URL` | нет | Только для запуска backend вне Docker; в контейнерах собирается в `compose.yaml` |
| `DATA_MODE` | нет | `live` — реальные источники (при сбое — снимок), `offline` — только снимки |
| `PARSER_INTERVAL_MIN` | нет | Период сбора данных (360 мин) |
| `NOTIFY_INTERVAL_MIN` | нет | Период проверки уведомлений (30 мин) |

## 8. Внешние сервисы и интеграции

| Сервис | Для чего | Как |
|---|---|---|
| **MAX Bot API** (`platform-api2.max.ru`) | сообщения, кнопки, уведомления | long polling (публичный адрес боту не нужен). API использует сертификат Национального УЦ Минцифры — он добавлен в образ (`infra/certs`, переменная `NODE_EXTRA_CA_CERTS`) |
| **MAX Bridge** | `initData`, диплинк `start_param`, кнопка «Назад», вибрация, `openLink`, `shareContent` | скрипт в `index.html` |
| **Работа России** — открытые данные (`opendata.trudvsem.ru`) | вакансии для стажёров и без опыта в IT | официальный открытый API |
| **Хабр Карьера** (`career.habr.com/vacancies?qid=1`) | вакансии уровня «Стажёр» | разбор публичных HTML-страниц, разрешённых `robots.txt`; внутренние API сайта не используются |
| **Cloudflare Quick Tunnel** | HTTPS для мини-приложения без VPS | контейнер `tunnel`, только для разработки и проверки |

API hh.ru на момент разработки отвечает 403 на запросы без ключа приложения, поэтому не используется (см. «Известные ограничения»).

## 9. Работа с данными

**Источники и достоверность.** Каждая стажировка хранит источник, ссылку на первоисточник, дату получения и флаг `is_synthetic`. В интерфейсе всегда видно, откуда запись и когда обновлена.

| Источник | Тип данных | Пометка в интерфейсе |
|---|---|---|
| Работа России | реальные | — |
| Хабр Карьера | реальные | — |
| Справочник программ (`backend/seed/programs.json`) | **модельные сроки** | «демо-сроки» + пояснение в карточке |
| Снимок источника (`backend/seed/snapshots`) | реальные на дату снимка | «снимок от ДД.ММ.ГГГГ» |

**Справочник программ.** 12 сезонных программ стажировок крупных компаний. Названия компаний и ссылки реальные (проверены), описания обобщённые, **даты наборов демонстрационные**. Даты задаются смещением от дня первой загрузки справочника, поэтому дедлайны честно приближаются со временем — это позволяет проверить сценарий напоминаний. В пилоте справочник должен поддерживать карьерный центр вуза.

**Обработка.** Адаптеры приводят записи к единому формату. Направление (14 категорий) и стек (23 технологии) определяются правилами из `backend/src/domain/taxonomy.ts`. Не-IT вакансии отсеиваются. Исчезнувшие из источника записи скрываются, но не удаляются, так как на них могут ссылаться отслеживания.

**Скоринг** (`backend/src/domain/match.ts`) прозрачный, без ML: направление — 40, стек — 30, курс — 15, формат/город — 15. Каждое слагаемое показывается пользователю как причина или предупреждение. LLM не используется.

**Персональные данные (152-ФЗ).** Храним только id пользователя MAX, имя из профиля MAX и добровольно указанный профиль: направления, стек, курс, город, формат. ФИО, телефон, резюме не запрашиваются. Заявка подаётся на сайте работодателя. Доступ к API — только по сессии, выданной после проверки подписи `initData` (HMAC-SHA256). Сессия хранится в памяти клиента.

## 10. Работа с тестовыми данными

- **Без интернета / воспроизводимо:** `DATA_MODE=offline` — используются снимки из `backend/seed/snapshots` и справочник программ.
- **Обновить снимки:** `cd backend && npm ci && npm run snapshot`.
- **Сбросить данные и «якорную» дату справочника:** `docker compose down -v && docker compose up -d`.
- **Проверка в браузере без MAX:** `ALLOW_DEV_AUTH=true`, открыть http://localhost:8080 — вход демо-пользователем (id 1000001, ему уведомления не отправляются).
- **Диплинк в браузере:** http://localhost:8080/?startapp=i1 — откроется карточка с id 1.

## 11. Пошаговый сценарий проверки

1. `docker compose up -d --build`. Через ~30 с `docker compose ps`: `api` — `healthy`, остальные — `Up`.
2. `docker compose logs worker` — строки «Источник curated/habr_career/trudvsem: сохранено N записей». Сбор «Работы России» занимает ~1–2 минуты: их API отвечает медленно.
3. `docker compose logs bot` — «Бот запущен: @<ник>».
4. В MAX открыть бота → «Начать» → выбрать направление, курс, город.
5. Нажать «🔥 Топ-3 прямо здесь» → «⭐ Отслеживать» у программы с ближайшим дедлайном.
6. Нажать «🚀 Открыть подборку» → откроется мини-приложение с подборкой под профиль.
7. Изменить фильтры (например, «Фильтры» → стек Python), открыть карточку, нажать «Подать заявку на сайте».
8. Проверить уведомление: `docker compose restart worker` — для отслеживаемой программы с дедлайном ≤ 7 дней в чат придёт напоминание. Кнопка «Открыть карточку» откроет мини-приложение сразу на ней.
9. Автотесты: `cd backend && npm ci && npm test` — 11 тестов (подпись initData, сессии, классификация, скоринг, статусы, парсеры на снимках).

## Использование возможностей MAX (платформенный бонус)

Сверх минимальных требований (бот + мини-приложение) продукт использует связку возможностей MAX, которая и создаёт основную ценность — «не пропусти дедлайн»:

1. **Диплинк из уведомления в карточку.** Воркер присылает в чат напоминание о дедлайне. Кнопка `open_app` с `payload=i<id>` открывает мини-приложение, которое читает `start_param` из подписанного `initData` и сразу показывает нужную карточку. Работает от начала до результата: «Отслеживать» → напоминание → карточка → «Подать заявку».
2. **Проверка подписи `initData`** на сервере (HMAC-SHA256): личность пользователя берётся только из подписанных данных, профиль общий для бота и мини-приложения.
3. **MAX Bridge:** нативная кнопка «Назад», тактильный отклик на действия, `openLink` для перехода к заявке, `shareContent` для отправки стажировки другу.
4. **MAX UI:** компоненты и цветовые токены MAX, светлая и тёмная тема.
## 13. Известные ограничения

- Сроки наборов в справочнике программ — **демонстрационные** (помечены в интерфейсе).
- API hh.ru недоступен без ключа приложения — источник не подключён.
- У вакансий из «Работы России» и Хабр Карьеры нет дедлайнов (постоянный набор), поэтому напоминания о дедлайнах работают для программ из справочника. Для вакансий работает дайджест новых подходящих позиций.
- Хабр Карьера отдаёт на публичных страницах только краткую карточку; полное описание — по ссылке.
- Классификация направлений — на правилах; редкие позиции могут попасть в «Другое в IT».
- Бот работает через long polling. Документация MAX рекомендует webhook для production — это следующий шаг при переходе на постоянный домен.
- Cloudflare Quick Tunnel из России доступен только через VPN, а его адрес меняется при перезапуске. Для проверки и пилота используется VPS (`compose.vps.yaml`).
- Поиск и скоринг выполняются в памяти процесса API: достаточно для тысяч записей. Для масштаба региона и выше — перенос в SQL и индексы.

## 14. Остановка и повторный запуск

```bash
docker compose stop                      # остановить, данные сохраняются
docker compose start                     # запустить снова
docker compose --profile tunnel down     # остановить всё, включая туннель
docker compose down -v                   # удалить контейнеры и данные БД
docker compose up -d --build             # пересобрать после изменений
```
